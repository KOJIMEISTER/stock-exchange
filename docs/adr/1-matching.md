## Контекст

Нужно выбрать простой и предсказуемый алгоритм матчинга для MVP биржи, чтобы быстро реализовать limit/market ордера без сложных структур данных. Для MVP важнее прозрачность логики и скорость разработки, чем максимальная производительность под большую нагрузку.

## Решение

Использовать приоритет Price-Time: сначала лучшая цена, при равной цене — более ранний ордер по времени размещения. Стакан хранить в двух отсортированных массивах: bids по убыванию цены, asks по возрастанию цены, внутри одного ценового уровня соблюдать FIFO. Market-ордер матчить последовательно против лучших встречных заявок до полного исполнения или исчерпания ликвидности, limit-ордер — либо исполнять сразу, либо оставлять в стакане.

## Рассмотренные альтернативы

Хранить ордера в неотсортированных массивах и искать лучшую цену при каждом матчинге — проще в коде, но хуже по предсказуемости и скорости обработки. Использовать map по ценам и очередь ордеров на каждом уровне — лучше масштабируется и удобнее для отмен, но заметно сложнее для MVP. Использовать деревья и другие более сложные структуры данных — избыточно на текущем этапе.

## Трейд-оффы и последствия

Решение упрощает разработку и отладку, а также делает правила исполнения очевидными для пользователя. Недостаток в том, что вставка и удаление в отсортированном массиве имеют линейную стоимость, поэтому при росте числа ордеров производительность начнет ухудшаться. Если проект упрется в нагрузку, следующим шагом будет переход на структуру price level -> queue/orders с отдельной индексацией для быстрых отмен.
